## Corrections to prior claims

- OLD SHARED POLICY SCOPE — prameyallc.github.io/edu-app-privacy scopes itself to apps with no accounts, no uploads, and no health or financial data, and (per the portfolio pattern) implies no networking. OmniBuild fits the 'no accounts / no uploads / no health data' part, but the no-networking implication is FALSE. TRUTH: OmniBuild makes an outbound HTTPS connection to huggingface.co to download AI model weights when the user starts the download in Settings. It carries a public model repo name plus the IP address and headers any request reveals; it carries no user content.
- README.md line 23 states OmniBuild is 'Fully on-device — questions never leave your iPhone'. The second half is TRUE; the first half over-claims. TRUTH: questions and logs never leave the device, and inference is fully on-device — but the app is not fully offline. It downloads model weights from Hugging Face over HTTPS on first use. The accurate formulation is 'your content never leaves your device; the model file is downloaded once from Hugging Face'.
- Info.plist NSHealthShareUsageDescription claims OmniBuild 'optionally accesses HealthKit (steps, sleep, activity) with your explicit permission to provide educational correlations and insights'. FALSE. TRUTH: there is zero HealthKit code in the repo. The app cannot access HealthKit, has never asked for it, and shows no permission prompt. The string describes a feature that does not exist.
- project.pbxproj INFOPLIST_KEY_NSHealthShareUsageDescription and INFOPLIST_KEY_NSHealthUpdateUsageDescription assert 'No health data collected' and 'OmniBuild does not read or store health data' — the conclusions are TRUE but they are attached to permission descriptions for a permission the app never requests, and they directly contradict the Info.plist string above. TRUTH: the app processes no health data at all, and no health permission string should ship.
- OmniBuild.entitlements declares com.apple.developer.healthkit, com.apple.developer.healthkit.access = [health-records], and healthkit.background-delivery. These assert a health-data capability, including the RESTRICTED health-records entitlement. FALSE as a description of the app. TRUTH: no HealthKit code exists; all three entitlements must be removed.
- App/RootView.swift:40 calls integrateHealthKitInsights(steps: 6500, sleepHours: 7.2) on every launch, and AppDataService.swift:191-195 renders it as user-visible text about the user's activity. FALSE and user-facing. TRUTH: 6,500 steps and 7.2 hours are hardcoded literals in the source. They are not the user's data and not anyone's data. The feature and its output must be deleted.
- CloudSyncService.swift:7-9 documents 'lightweight CloudKit roaming... Roams profile, habits, decisions, streaks, avoided estimates' with 'Sync Now + status in standardized Settings'. FALSE on both counts. TRUTH: forceSyncNow() sets a timestamp and writes a log line; it transmits nothing. And there is no Sync Now control in the UI — the service has no caller anywhere in App/, Features/, Domain/ or DesignSystem/.
- OmniBuild.entitlements declares iCloud container iCloud.com.omni.OmniBuild with CloudKit and CloudDocuments services, asserting a cloud sync capability. FALSE as a description of the app. TRUTH: nothing syncs; the entitlements back dead code and must be removed.
- /Users/sbkoth/work/Omni/OmniBuild/OmniBuild/PrivacyInfo.xcprivacy (tracked in git) declares NSPrivacyCollectedDataTypeHealth and NSPrivacyCollectedDataTypeSensitive with purpose NSPrivacyCollectedDataTypePurposeHealth, plus Camera, PhotoLibrary, FileTimestamp, HealthKit and CloudKit required-reason entries, and comments about 'Dental photos and derived oral health analysis'. ENTIRELY FALSE for this app — it is a copy of the OmniDent manifest. TRUTH: OmniBuild collects no data types at all, uses no camera, no photo library, no HealthKit and no CloudKit. The file is not in the build today (the pbxproj references only the root manifest) but must be deleted.
- The prior PrivacyInfo.xcprivacy at the repo root was not a property list at all — it was the prose string 'FULL: dental copy-paste fixed to project/habit/photo + VLM/export/consent notes (workspace exact).' It made no valid privacy declaration and would have drawn an automated App Store Connect rejection. TRUTH: replaced in wave 1 with a valid manifest declaring no tracking, no collected data types, and one required-reason entry (UserDefaults, CA92.1).
- project.pbxproj INFOPLIST_KEY_NSCameraUsageDescription states 'OmniBuild uses optional camera for future educational imaging literacy examples'. FALSE as a present-tense capability. TRUTH: there is no AVCapture code, no camera UI, and no code path that requests camera access. A purpose string for an unrequested permission is itself a defect.

The substance is TRUE, but it shipped alongside iCloud and HealthKit entitlements that said the opposite, and alongside a sync service documented as roaming user records.
