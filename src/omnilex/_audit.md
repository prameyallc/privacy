# OmniLex — data-flow audit

AUDIT OF prameyallc/OmniLex `main` at 818232c (merge of OmniLex#187, the 2026-09-23 privacy fixes), PLUS the paired app PR OmniLex#188 (branch `feat/privacy-followups-2026-09-24`; owner answers of 2026-09-24: Watch and Mac signed for iCloud key-value storage). Regenerated 2026-09-24 on the owner's instruction ("regenerate from main"); it replaces the 2026-08-08 audit, which described a tree that no longer exists (DuckDuckGo egress, no StoreKit, no iCloud, camera/photo/local-network purpose strings, Phi-2, a Keychain wrapper). Findings are from source; where docs and code disagreed I trusted code. Paths are relative to the OmniLex repository. Unpublished: this file informs `policy.md` and is not built into the site.

PLATFORMS AND TARGETS: one multiplatform app target `OmniLex` (bundle `legal.prameya.OmniLex`; iPhone, iPad, Mac, Apple Vision Pro); `OmniLexTV` (tvOS, same bundle ID since 2026-09-23); `OmniLexWatch` (`legal.prameya.OmniLex.watch`) with its complication extension `OmniLexWatchWidgets` (`legal.prameya.OmniLex.watch.widgets`); the iOS Home Screen widget `OmniLexWidgets` (`legal.prameya.OmniLex.widgets`). Deployment floor 27.0 everywhere. English only.

ACCOUNTS / BACKEND: none. No sign-in of any kind, no account API, no Prameya server. No analytics, advertising, attribution, crash-reporting or remote-config SDK. Logging is OSLog (`OmniLogger`, subsystem `legal.prameya.OmniLex`) on the device. MetricKit summaries (`LexCore/OmniCore/Telemetry/MetricKitBridge.swift`) are written to the device log only.

DOCUMENT IMPORT: `.fileImporter` in Home and the vault plus drag-and-drop; one list of types, `TextExtractionService.importableContentTypes` = PDF, Word (.docx), plain text, RTF, images (the watchOS/tvOS build of LexCore has no .docx). Security-scoped bookmarks keep a pointer to the user's file; the file is not moved or copied to the cloud. The sample NDA is the bundled CC0 `mutual_nda` template added as a vault document with no file behind it (`SampleNDA`). No camera, no photo library, no local network: the only purpose string in the project is `NSDocumentsFolderUsageDescription`, and `AppleComplianceTests` fails the build if a camera, photo or local-network string returns.

TEXT EXTRACTION: PDFKit for text PDFs; Vision OCR for scanned PDFs and images; .docx via AppKit `officeOpenXML` on the Mac and `WordDocumentReader` (ZIPFoundation 0.9.20 + `XMLParser`) on iPhone, iPad and Vision Pro. All on the device.

STORAGE ON THE DEVICE: SwiftData store opened by `OmniLexStore.open()` with `cloudKitDatabase: .none` (no CloudKit, no iCloud container in any entitlements file). Models: Document (title, bookmark, extracted text, summary, tags, notes), reading-priority flags, chat messages, templates, notes, search chunks with embeddings. `StoreFileProtection` sets `completeUnlessOpen` on the store and its `-wal`/`-shm` on iPhone, iPad and Vision Pro (best-effort; no per-file class on the Mac). The store is not excluded from backups (D-7, owner 2026-09-23); the model cache and `ExportScratch` are (`isExcludedFromBackup` in `OmniLexContainerPaths` / `ExportScratch`). UserDefaults: appearance (`app.appearance`), onboarding seen, first-run acknowledgement date, lowest reading priority, On-device answers (`lex.onDeviceAnswers`), inference preferences incl. Download over cellular, selected model and known-downloaded models, download resume data, recently opened document UUIDs (`omnilex.lastOpenedDocumentID`, `omnilex.recentDocumentIDs`), re-check reminder switch and up to 200 opened pack IDs (`lex.packRecheckReminders*`), answered reminder IDs, the free-first-review document UUID (`monetization.firstReview.documentID`), the sample NDA's UUID. No Keychain use: `SecureStore` was deleted 2026-09-23 (`InAppPrivacyCopyTests.nothingInTheKitUsesTheKeychain`).

AI ON THE DEVICE: three Apache-2.0 Qwen3 4-bit MLX conversions from `mlx-community` pinned by commit (0.6B `73e3e38d` ~420 MB, 1.7B `3b1b1768` ~1.1 GB default, 4B `4dcb3d10` ~2.5 GB), shown as Compact / Standard / Large. Only Settings ▸ On-Device AI downloads (`MLXSelectedModelManager.load()`); every feature goes through `MLXLLMClient` → `loadFromThisDevice()` and never downloads (`ModelDownloadConsentTests`). Ask: Apple Intelligence (`SystemLanguageModel`) first where ready, then a model already on disk, then "cannot answer" (D-9); the On-device answers switch turns Ask off. Watch Ask is forwarded to the iPhone and answered the same way (`WristAskAnswer`). TV Ask is extractive over the bundled library and runs no model. Semantic search uses `NLEmbedding` on the device. The legal skill pack, reference library, clauses and templates ship in the bundle; nothing is fetched at runtime.

NETWORK EGRESS FROM OMNILEX'S OWN CODE — exactly one: Hugging Face model download (`HubClient` from swift-huggingface 0.9.0 via `HubDownloaderBridge` / `RobustDownloader`), `huggingface.co` redirecting to `*.cdn.hf.co`, carrying repository, revision and file names plus ordinary request metadata. Network symbols appear only under `Intelligence/MLX/{Download,Manager,Inference,Policy}` (plus comments and error classification in LexCore); `OmniLexEgressTests` enforces it. ATS `NSAllowsArbitraryLoads = false`. The DuckDuckGo Case Story path is deleted (the feature is now Document Background, no network). swift-huggingface also links an inference client (`router.huggingface.co`) and an OAuth manager; no OmniLex source calls either.

APPLE SERVICES (Apple frameworks, not OmniLex networking):
1. iCloud key-value storage, four keys only (`ContinuityKeys.allCloudKeys`): `continue.payload` (surface, pack ID, a document UUID, date), `appearance.mode`, `homeScreen.glance` (a document UUID + the fixed "Last matter" / "Open in OmniLex", D-1), `homeScreen.pendingOpen` (a UUID or "continue"). Never a title, file name or text (`LastMatterGlanceTests`). Every target that touches the store signs with `com.apple.developer.ubiquity-kvstore-identifier` = `$(TeamIdentifierPrefix)legal.prameya.OmniLex`: iOS/iPadOS/visionOS app, iOS widget, TV (before this PR); Mac app, Watch app, Watch complications (this PR, owner 2026-09-24; `KVSEntitlementContractTests`). Writers: the app on iPhone, iPad, Vision Pro and now Mac (`ContinueSession`, `HomeScreenMatterHost`), and the Watch when Pin this topic is confirmed (`ContinuityStore.pinPack`). Readers: the widget, TV, the Watch app and complication, and the app itself (pending open, legacy-glance scrub). The widget's pending open is consumed only on iPhone/iPad (`HomeScreenMatterHost.consumePendingOpen` is `#if os(iOS)` in this PR), so the Mac and Vision Pro no longer take an iPhone's request. Delete All (any of the four app platforms) removes all four keys, which removes them account-wide; deleting the document the glance names does the same; deleting another document strips its UUID from the continue payload (`DeletedDocumentForgottenTests`).
2. The Watch (this PR): reads through `WristContinue` — iCloud and WatchConnectivity payloads merge newest-first by `updatedAt`, only a `didChangeExternallyNotification` read may clear them, a payload without a topic drops the Continue/Pin prompts, a removed appearance entry returns to System; the notification is handled on the main queue. The complication shows "Continue" or "Learn" only; before this PR it printed the raw pack ID. `WristContinueTests` pin it.
3. Handoff (`legal.prameya.OmniLex.continue`, not eligible for search) on iPhone, iPad, Mac, Vision Pro with the same payload; a receiving device opens the document only if it exists locally.
4. WatchConnectivity (iPhone ↔ Watch): continue payload and re-check prompts to the Watch; Confirm / Snooze / Not now and Ask iPhone questions to the iPhone; answers back.
5. StoreKit 2: `legal.prameya.omnilex.pro.monthly` / `.annual` / `.lifetime`, one `isPro` flag from `Transaction.currentEntitlements` held in memory; no transaction IDs or dates stored; purchases on iPhone, iPad, Mac, Vision Pro only.
6. Local notifications: only behind the Settings switch (off on a fresh install); `DeadlineReminderScheduler.enable()` is the only permission request; a tap only opens the topic (`ReminderOptInContractTests`).
7. Clipboard: Document Background Copy is `.localOnly` with a 120-second expiry on iPhone/iPad/Vision Pro, and kept to the Mac on macOS.
8. Links open in the browser or mail app; nothing of the user's is added.

ENTITLEMENTS (after this PR): iOS/visionOS — increased memory limit, KVS. macOS — app sandbox, user-selected files read-only and read-write (PDF export destinations), network.client, cs.allow-jit, KVS. Fallback `OmniLex.entitlements` — network.client. Widget, TV, Watch, Watch complications — KVS only. No CloudKit, no App Group, no push, no HealthKit anywhere.

PRIVACY MANIFESTS: `App/*/PrivacyInfo.xcprivacy` declare no tracking, no tracking domains, no collected data types; required-reason APIs UserDefaults CA92.1, FileTimestamp C617.1, DiskSpace E174.1 (`RequiredReasonAPITests`). ZIPFoundation ships its own manifest (FileTimestamp 0A2A.1).

HEALTH DATA: none. No HealthKit, no health fields; MHMDA / Nevada SB 370 do not apply; no health-data page.

## Corrections to prior claims

- 2026-08-08 audit, "no StoreKit": SUPERSEDED. OmniLex Pro is sold through StoreKit 2 (three products); the policy describes it and says no transaction identifiers are stored, which matches `EntitlementManager`.
- 2026-08-08 audit, "no iCloud entitlement in any of the three .entitlements files; nothing syncs": SUPERSEDED. Documents still do not sync (`cloudKitDatabase: .none`, no container), but four small KVS entries do, and after this PR the Mac and the Watch share them. The published policy said until this PR that "on a Mac these entries stay on the Mac" and that the Watch got the information only from the iPhone; both are corrected in the 24 September revision.
- 2026-08-08 audit, DuckDuckGo egress "still present": RESOLVED. `WebSearchService.swift` is gone; `OmniLexEgressTests` fails the build if outbound networking appears outside the model downloader.
- 2026-08-08 audit, camera / photo-library / local-network purpose strings and the "100% on-device" copyright and manifest comments: RESOLVED. The only purpose string is `NSDocumentsFolderUsageDescription`; the manifest comment now lists Hugging Face and the Apple services.
- 2026-08-08 audit, "no explicit file protection": RESOLVED on iPhone, iPad and Vision Pro (`completeUnlessOpen`, best-effort); the Mac relies on FileVault, as the policy says.
- 2026-08-08 audit, Keychain wrapper `SecureStore` ("com.omni.secure"): RESOLVED. Deleted; nothing in the kit uses the Keychain.
- 2026-08-08 audit, Phi-2 in the catalog and the Xet/CAS host note: SUPERSEDED. Phi-2 is removed (LEX-023); the download is described as `huggingface.co` → `*.cdn.hf.co`.
- Watch complication (before this PR): printed the raw reference-topic pack ID on the watch face. FIXED in this PR ("Continue" / "Learn").

## Open questions

- OWNER PORTAL: enable iCloud (key-value storage) on the App IDs `legal.prameya.OmniLex.watch` and `legal.prameya.OmniLex.watch.widgets`, and make sure the Mac provisioning profile for `legal.prameya.OmniLex` includes it. Until then a signed Watch or Mac build cannot carry the entitlement, and the behaviour the 24 September policy describes starts with the first build uploaded after the app PR merges and the capabilities exist.
- Merge order: OmniLex#188 first, this privacy PR right after it; the next uploaded build must include the app PR, because the page describes it.
- The widget's pending-open key is consumed only at a cold launch (`ContinueSession.task`). If the iPhone app is already running when the widget or shortcut sets it, the key stays in iCloud until OmniLex next starts on any iPhone or iPad on the account (the store is shared), and that launch opens its own last document, if it has one. The policy says exactly that ("removed the next time OmniLex starts on an iPhone or iPad"; review of #188 replaced "set for a moment … removed when the app opens there", which was false for a warm start). A warm-start consumer would make the widget tap itself work while the app is running.
- WatchConnectivity: `PhoneWristBridge.send` puts each event in `updateApplicationContext`, which keeps only the last one, so an unreachable Watch receives the continue payload but not the approvals list sent just before it. Not a disclosure issue; a delivery gap.
- Third-party packages: the package-by-package review of the dependencies' own privacy manifests (LEX-017) is still outstanding; the policy says so.
- Apple's developer-facing App Store reporting: not audited; the policy makes no claim about its contents.
- App Store Connect (RESOLVED 2026-09-24, read-only check by the main session, recorded in `docs/superpowers/plans/privacy-fix-owner-answers-2026-09-24.md`): no Connect write is needed. The monthly, annual and lifetime localizations read "On-device document search and clause flags.", the subscription-group localization is just "OmniLex Pro", and the iOS, Mac, TV and visionOS 1.0 listing text has no "never leave" claim. The retired phrase existed only in the repo (ProCatalog/PaywallCopy, fixed in OmniLex#187) and in docs.
